## 稀疏矩阵格式

### CSR (Compressed Sparse Row)

CSR 格式使用三个数组压缩存储稀疏矩阵：

```
原始矩阵 (3×4):
┌─────┬─────┬─────┬─────┐
│  1  │  0  │  2  │  0  │  第 0 行
├─────┼─────┼─────┼─────┤
│  0  │  3  │  0  │  4  │  第 1 行
├─────┼─────┼─────┼─────┤
│  5  │  0  │  0  │  6  │  第 2 行
└─────┴─────┴─────┴─────┘

CSR 表示:
┌────────────────────────────────────────────────┐
│ values:      [1, 2, 3, 4, 5, 6]               │
│ col_indices: [0, 2, 1, 3, 0, 3] ← 列索引      │
│ row_ptrs:    [0, 2, 4, 6]       ← 行起始位置  │
└────────────────────────────────────────────────┘

访问第 i 行: 数据范围 [row_ptrs[i], row_ptrs[i+1])
```

**复杂度分析:**
- 存储空间: `O(nnz + rows)` — 与矩阵规模无关
- 随机访问: `O(log nnz_per_row)` — 需要二分查找
- 行遍历: `O(nnz_per_row)` — 连续内存访问

### ELL (ELLPACK)

ELL 格式使用固定宽度的二维数组，按列优先存储：

```
原始矩阵 (4×4, max_nnz_per_row=2):
┌─────┬─────┬─────┬─────┐
│  1  │  0  │  2  │  0  │  第 0 行: [1, 2]
├─────┼─────┼─────┼─────┤
│  0  │  3  │  0  │  4  │  第 1 行: [3, 4]
├─────┼─────┼─────┼─────┤
│  5  │  6  │  0  │  0  │  第 2 行: [5, 6]
├─────┼─────┼─────┼─────┤
│  7  │  0  │  0  │  0  │  第 3 行: [7, -] ← 填充
└─────┴─────┴─────┴─────┘

ELL Column-major 存储:
┌─────────────────────────────────────────┐
│ values:      [1, 3, 5, 7, 2, 4, 6, 0]  │
│                ↑  ↑  ↑  ↑  ↑  ↑  ↑  ↑   │
│               row0 row1 row2 row3   (k=0)
│ col_indices: [0, 1, 0, 0, 2, 3, 1, -1] │
│                ↑  ↑  ↑  ↑              │
│               (k=1)                    │
│ 存储布局: [row0_k0, row1_k0, ..., row0_k1, ...] │
└─────────────────────────────────────────┘
```

**GPU 访问优化:**
- 线程 i 访问第 k 列: `index = k * num_rows + i`
- 相邻线程访问连续地址 → 完全合并访存
- 无 bank conflict

## Kernel 设计

### 调度策略决策树

```
                 矩阵特征分析
                      │
         ┌────────────┴────────────┐
         │                         │
    ┌────┴────┐              ┌─────┴──────┐
    │ FORMAT  │              │  统计特征   │
    └────┬────┘              └─────┬──────┘
         │                         │
    ELL ─┼─→ ELL Kernel    ┌──────┴──────┐
         │                 │             │
        CSR          avg_nnz < 4?   skewness < 10?
                            │             │
                          Yes            No
                            │             │
                       ┌────┴────┐    ┌───┴────┐
                       │ Scalar  │    │ Vector │──Yes──→ Vector CSR
                       │  CSR    │    │  CSR   │
                       └─────────┘    └────────┘
                                           │
                                          No
                                           │
                                      ┌────┴────┐
                                      │  Merge  │
                                      │  Path   │
                                      └─────────┘
```

### Kernel 特性对比

| Kernel | 并行策略 | 同步开销 | 负载均衡 | 最佳场景 |
|:-------|:---------|:--------:|:--------:|:---------|
| **Scalar** | 1 线程/行 | 无 | 差 (行长度差异) | avg_nnz < 4 |
| **Vector** | 1 Warp/行 | Warp 内归约 | 中等 | 均匀分布矩阵 |
| **Merge Path** | 均匀划分 | 原子操作 | 完美 | 极度不均匀矩阵 |
| **ELL** | 1 线程/行 | 无 | - | ELL 格式矩阵 |

### Merge Path 算法详解

Merge Path 是解决 CSR 负载不均衡问题的关键算法：

```
行指针序列:   [0, 100, 101, 200]    (4 行，分布极不均匀)
非零元序列:   [0, ..., 99, 100, 101, ..., 199]

传统 CSR 问题:
- 行 0: 100 个非零元 → 1 线程处理 100 个元素
- 行 1: 1 个非零元  → 1 线程处理 1 个元素
→ 严重负载不均衡！

Merge Path 解决方案:
1. 将行指针序列和非零元序列视为两条有序路径
2. 在合并路径上均匀划分工作
3. 每个线程块处理相等的 (row, offset) 范围

对角线切割:
         row:  0      1    2      3      4
              [0]─[100]─[101]─[200]
               │╲   │╲    │╲    │╲
              [0]..[99][100][101]..[199]
               nz:

划分: 4 个线程块，每个处理 ~50 个非零元
→ 完美负载均衡！
```

## 内存管理

### RAII 设计模式

所有 GPU 资源均采用 RAII (Resource Acquisition Is Initialization) 模式管理：

```cpp
// CudaBuffer: 自动管理 GPU 内存
template<typename T>
class CudaBuffer {
    T* d_ptr_;           // 设备指针
    size_t size_;        // 元素数量
    size_t capacity_;    // 分配容量

public:
    explicit CudaBuffer(size_t n);   // 构造函数分配
    ~CudaBuffer();                    // 析构函数释放
    
    // 禁用拷贝，允许移动
    CudaBuffer(const CudaBuffer&) = delete;
    CudaBuffer(CudaBuffer&& other) noexcept;
};

// 使用示例: 异常安全
try {
    CudaBuffer<float> buf(1000000);  // 分配
    process_data(buf.get());          // 使用
    // 即使抛出异常，buf 也会被正确释放
} catch (...) {
    // 无需手动释放
}
```

### 执行上下文复用

`SpMVExecutionContext` 用于复用昂贵的纹理对象：

```cpp
class SpMVExecutionContext {
    cudaTextureObject_t tex_x_;     // 纹理对象 (创建昂贵)
    const float* cached_x_;         // 缓存的向量指针
    size_t cached_x_length_;        // 缓存的向量长度

public:
    SpMVExecutionContext();         // 构造函数
    ~SpMVExecutionContext();        // 析构时销毁纹理

    cudaTextureObject_t prepare_texture(
        const float* x, size_t n);  // 延迟创建/复用
};

// 性能优化: 多次调用复用纹理
SpMVExecutionContext ctx;
for (int iter = 0; iter < 100; iter++) {
    // 纹理只创建一次，后续复用
    spmv_csr(csr, d_x, d_y, &config, n, &ctx);
}
```

## 错误处理机制

### 分层错误处理

```
┌─────────────────────────────────────────┐
│          用户层 (User Code)              │
│    if (result.error_code != 0) {...}    │
├─────────────────────────────────────────┤
│          接口层 (API Layer)              │
│    return SpMVResult{..., error_code};  │
├─────────────────────────────────────────┤
│          运行时层 (Runtime)              │
│    CUDA_CHECK_MALLOC(cudaMalloc(...));  │
├─────────────────────────────────────────┤
│          驱动层 (CUDA Driver)            │
│    cudaError_t err = cudaMalloc(...);   │
└─────────────────────────────────────────┘
```

### 错误码体系

```cpp
enum class SpMVError : int {
    SUCCESS = 0,              // 成功
    INVALID_DIMENSION = -1,   // 维度不匹配
    CUDA_MALLOC = -2,         // GPU 内存分配失败
    CUDA_MEMCPY = -3,         // 内存拷贝失败
    KERNEL_LAUNCH = -4,       // Kernel 启动失败
    INVALID_FORMAT = -5,      // 矩阵格式错误
    FILE_IO = -6,             // 文件操作失败
    OUT_OF_MEMORY = -7,       // 内存不足

};

// 错误信息转换
const char* spmv_error_string(SpMVError err);
// 返回: "Invalid dimension", "CUDA malloc failed", ...
```

## 性能优化策略

### 内存带宽优化

SpMV 是典型的**内存带宽受限**操作，优化重点是最大化带宽利用率：

```
算术强度 = 计算量 / 数据量
         = (2 × nnz FLOP) / (~20 × nnz bytes)
         ≈ 0.1 FLOP/Byte  <<  GPU 需求 (~10 FLOP/Byte)

→ 必须优化内存访问模式
```

**优化技术:**

| 技术 | 实现 | 效果 |
|:-----|:-----|:-----|
| **合并访问** | ELL Column-major | 消除非合并访存惩罚 |
| **纹理缓存** | `cudaTextureObject_t` | 提升随机访问性能 |
| **Warp 归约** | `__shfl_down_sync` | 消除 bank conflict |
| **预取** | 编译器自动优化 | 隐藏内存延迟 |

### 负载均衡优化

```
矩阵偏斜度 (Skewness) = max_nnz_per_row / (min_nnz_per_row + 1)

┌───────────────────────┬────────────────┬────────────────┐
│ Skewness              │ 推荐 Kernel    │ 原因           │
├───────────────────────┼────────────────┼────────────────┤
│ < 10 (均匀)           │ Vector CSR     │ Warp 协作高效   │
│ >= 10 (不均匀)        │ Merge Path     │ 完美负载均衡    │
│ < 4 (极稀疏)          │ Scalar CSR     │ 最小线程开销    │
└───────────────────────┴────────────────┴────────────────┘
```

## 设计决策记录

### ADR-001: 静态库而非动态库

**决策**: 提供静态库 (`.a`) 而非动态库 (`.so`/`.dll`)

**原因**:
- ✅ 简化部署，无运行时依赖
- ✅ 链接时优化机会
- ✅ CUDA 运行时静态链接更稳定
- ✅ 避免符号版本问题

**权衡**:
- ❌ 可执行文件更大
- ❌ 更新库需要重新编译

### ADR-002: RAII 资源管理

**决策**: 所有 GPU 资源采用 RAII 模式

**原因**:
- ✅ 异常安全
- ✅ 避免内存泄漏
- ✅ 代码更清晰

**实现**:
- `CudaBuffer<T>`: GPU 内存
- `CudaTimer`: CUDA Events
- `SpMVExecutionContext`: 纹理对象

### ADR-003: 自动 Kernel 选择

**决策**: 基于矩阵统计特征自动选择最佳 Kernel

**准则**:
```cpp
SpMVConfig spmv_auto_config(const CSRMatrix* csr) {
    auto stats = csr_compute_stats(csr);
    
    if (stats.avg_nnz_per_row < 4)
        return {SCALAR_CSR, ...};
    if (stats.skewness < 10)
        return {VECTOR_CSR, ...};
    return {MERGE_PATH, ...};
}
```

**优势**:
- 用户无需了解 Kernel 细节
- 自动适应不同矩阵特征
- 保证良好性能下限

### ADR-004: 纹理缓存可复用

**决策**: 提供 `SpMVExecutionContext` 复用纹理对象

**背景**:
- 创建/销毁 `cudaTextureObject_t` 开销高 (~100μs)
- PageRank 等迭代算法需要频繁 SpMV 调用

**解决方案**:
- 执行上下文缓存纹理对象
- 延迟创建，自动复用
- 析构时自动清理
